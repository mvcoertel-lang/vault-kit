Vault-Kit

Anleitung · Windows und Mac

Ordnerstruktur, Regeln, Gedächtnis und Wissensgraph für Claude Code

Das Kit macht aus dem Ordner, den Claude Code öffnet, einen geregelten Arbeitsplatz: Ergebnisse landen in Dateien, Gelerntes im Memory, und ein Wissensgraph zeigt, was wie zusammenhängt. Alles bleibt als lesbare Datei auf dem eigenen Rechner, ohne Cloud-Index und ohne Datenbank.

  • Dauer etwa fünf Minuten
  • System Windows 11 oder macOS
  • Quelle github.com/mvcoertel-lang/vault-kit

Was sich ändert

Vorher und Nachher

Claude Code liest zu Beginn jeder Sitzung Dateien ein: eine Kette von CLAUDE.md-Dateien und ein Memory-Verzeichnis. Ohne Struktur wachsen beide ungeordnet, und vieles bleibt im Chat liegen. Das Kit legt fest, wo was hingehört.

Zum Zeigen: erst „Vorher“, dann „Nachher“.
Thema Ohne Kit Mit Kit
Ergebnisse
Ohne Kit

Die Antwort steht im Chat und ist nach dem Schließen nur noch im Verlauf zu finden.

Mit Kit

Jedes Ergebnis wird eine Datei im Projektordner, zum Beispiel in 04_Output.

Wissen über Sitzungen hinweg
Ohne Kit

Nach /clear oder in einer neuen Sitzung ist das Gelernte weg; man erklärt es erneut.

Mit Kit

Ein Fakt wird eine Memory-Datei. MEMORY.md ist der Index und wird bei jedem Start geladen.

Zahlen
Ohne Kit

Claude nennt Zahlen aus dem Gedächtnis, ohne Quelle.

Mit Kit

Zahlen kommen aus einer Datei in 08_Reference und werden mit Pfad zitiert.

Anweisungen
Ohne Kit

Eine einzige CLAUDE.md wächst mit jeder Regel. Jede Runde liest alles mit und wird teurer und unschärfer.

Mit Kit

Eine Kette aus Global, Vault und Projekt. Geladen wird nur, was für die aktuelle Arbeit gilt.

Überblick
Ohne Kit

Was es schon gibt und was zusammenhängt, steht nirgends.

Mit Kit

Der Wissensgraph _Index/graph.html zeigt Memory, Skills, Projekte und Anweisungen mit ihren Verbindungen.

Wiederkehrende Aufgaben
Ohne Kit

Vorgehen, Format und bekannte Fallen werden jedes Mal neu erklärt.

Mit Kit

Skills für wiederkehrende Aufgaben und ein Arbeitsmodus-Command je Projekt, das die Projektregeln lädt.

Freigaben
Ohne Kit

Claude fragt bei fast jedem Befehl nach, auch bei rein lesenden.

Mit Kit

Freigaberegeln erlauben lesende Befehle, Änderungen im Vault laufen ohne Rückfrage (acceptEdits). Löschen, curl und git push fragen weiterhin.

Ordner vorher

  • C:\Users\<name>\.claude\
    • settings.jsonfalls vorhanden
    • projects\<ordner>\Verläufe, je Startordner ein eigenes Memory

Kein fester Arbeitsordner, keine Regeln. Wer einmal einen anderen Ordner öffnet, landet in einem leeren Memory.

Ordner nachher

  • C:\Users\<name>\Claude\der Vault
    • CLAUDE.mdRegeln und Routing-Tabelle
    • 00_Method\ 00_Sources\Standards, wiederverwendbare Quellen
    • <Projekt>\eigene CLAUDE.md, Ordner 01 bis 09 nach Bedarf
    • _Index\graph.htmlWissensgraph
    • .claude\skills, agents, commands
  • C:\Users\<name>\.claude\
    • CLAUDE.mdZeiger auf den Vault
    • settings.jsonautoMemoryDirectory (ein Memory für alle Sitzungen), Freigaberegeln, Hooks
    • tools\vault-index.py, graph.template.html, index-zusammenfassen.py und weitere
    • projects\<slug>\memory\MEMORY.md und eine Datei je Fakt

Auf dem Mac dieselbe Struktur unter ~/Claude und ~/.claude.

Der Wissensgraph

Er zeigt die Verbindungsschicht des Vaults, nicht den Inhalt der Dateien: was Claude weiß, wo es liegt und was zusammenhängt. Neubau am Ende jeder Sitzung, Anzeige offline im Browser. Kurze Erklärungen je Punkt schreibt Claude im Hintergrund.

  • Anweisungen · die CLAUDE.md-Kette
  • Memory · gelernte Fakten, eine Datei je Fakt
  • Skills · Fähigkeiten für wiederkehrende Aufgaben
  • Projekte · die Ordner im Vault
Wissensgraph ansehen (Beispiel-Vault)
Beispiel„Bau mir ein Proposal für eine SAP-Einführung bei einem Halbleiterhersteller.“

Ohne Kit

  1. Claude schreibt einen Entwurf in den Chat.
  2. Aufbau, Preislogik und Formulierungen besprecht ihr im Gespräch.
  3. Beim nächsten Proposal beginnt alles von vorn.

Mit Kit

  1. vault-init legt das Projekt an: Ordner, eigene CLAUDE.md und eine Routing-Zeile in der Vault-CLAUDE.md.
  2. PowerPoint-Master und Vergleichs-Proposals liegen in 08_Reference, der Entwurf entsteht in 04_Output.
  3. Was ihr dabei festlegt (Aufbau, Preislogik, Formulierungen), hält Claude als Memory fest.
  4. Beim nächsten Proposal liest Claude Memory und das alte Projekt und setzt dort an.

Das erste Proposal baust du gemeinsam mit Claude, nicht von Claude allein. Master vorgeben, zwei oder drei gute Vergleichs-Proposals als Kontext geben und Schritt für Schritt durchgehen. Claude weiß nicht von selbst, was ein gutes Proposal in deinem Umfeld ausmacht; ab dem zweiten wird wiederverwendet, was beim ersten entstanden ist.

In fünf Minuten

Installation

Zwei Wege. Weg A ist der kürzeste: Claude richtet das Kit selbst ein und fragt vor jedem Befehl um Freigabe. Weg B ist dieselbe Arbeit von Hand.

Weg A: Claude macht es

Empfohlen

In Claude Code einfügen (Desktop-App, Code-Tab, beliebiger Ordner, oder Terminal):

Richte mir das vault-kit ein: Lade https://github.com/mvcoertel-lang/vault-kit nach ~/vault-kit (git clone, sonst als ZIP), führe unter Windows `powershell -ExecutionPolicy Bypass -File install.ps1` aus, auf dem Mac `./install.sh`, und zeig mir die Ausgabe. Sag mir danach, welchen Ordner ich in Claude öffnen soll.

Danach weiter bei Schritt 3 von Weg B.

Im Alltag

Gewohnheiten

  • Immer den Vault öffnen, nie einen Unterordner.
  • /clearbei jedem Themenwechsel. Was bleiben soll, steht schon in einer Datei.
  • Neues Vorhaben: vault-initlegt das Projekt mit Ordnern und Regeln an.
  • /memory-reviewgelegentlich, wenn Claude am Sitzungsende daran erinnert.

Skills

  • analysisbelegte Auswertung, Vergleich, Empfehlung
  • dashboardKennzahlen und Charts
  • standalone-htmlSeiten, die offline aufgehen
  • automationSkripte und wiederkehrende Abläufe
  • markitdownPDF, Word, PowerPoint und Excel als Markdown lesen
  • vault-initneues Projekt anlegen
  • memory-writeein Fakt, eine Datei
  • context-auditmessen, was im Kontext liegt, und entschlacken

Agenten

  • scoutbreite Suche über viele Dateien, nur lesend
  • verifiereine Zahl oder Aussage gegenprüfen
  • librarianMemory und Quellenregister aufräumen
  • sichtprueferScreenshots und Bilder prüfen, ohne den Hauptkontext zu füllen

Commands

  • /methodStandards und Vorlagen laden
  • /sourcesQuellenregister
  • /memory-reviewMemory aufräumen lassen
  • /memory-benchmarkprüfen, ob das richtige Memory gefunden wird

Wenn etwas hakt

Fehlerbehebung

Windows„Die Ausführung von Skripts ist auf diesem System deaktiviert“
Den Installer mit -ExecutionPolicy Bypass starten wie oben. Hilft das nicht, sperrt eine Firmenrichtlinie Skripte: Weg A probieren oder die IT fragen.
Windowspython öffnet den Microsoft Store
Python von python.org installieren und „Add python.exe to PATH“ ankreuzen. Danach ein neues PowerShell-Fenster öffnen und den Installer erneut starten.
Windows und MacClaude fragt trotz Freigaberegeln weiter nach
Eine Firmenrichtlinie kann eigene Freigaberegeln abschalten (allowManagedPermissionRulesOnly). Dann bleibt es beim Nachfragen; das Kit ändert daran nichts.
Windows und MacWissensgraph leer oder veraltet
Von Hand neu bauen. Windows (PowerShell): 
py -3 "$env:USERPROFILE\.claude\tools\vault-index.py" "$env:USERPROFILE\Claude"
Mac (Terminal): 
python3 ~/.claude/tools/vault-index.py ~/Claude
Windows und MacMemory scheint leer
Meist ist ein Unterordner statt des Vaults geöffnet. Claude im Vault-Ordner neu starten.
Windows und Macclaude startet im Terminal nicht im Vault
Ein neues Fenster öffnen, damit das PowerShell-Profil bzw. ~/.zshrc neu geladen wird.

Hinweis: Die Windows-Fassung ist neu und wurde noch nicht auf einem Windows-Rechner getestet. Wenn etwas nicht klappt, bitte die Ausgabe des Installers mitschicken.
